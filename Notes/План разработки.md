# План создания и развития

Назад: [[Memory]] · Основание: [[Анализ ниши и выбор]] · Инструменты: [[Инструменты и скиллы]]

## Фаза 0. Проверка идеи (1–2 дня)
- [ ] Вбить в поиск RuStore 10–15 запросов («учёт расходов», «трекер подписок», «бюджет», «семейный бюджет» и т.д.), записать число приложений, рейтинги, дату последнего обновления у лидеров.
- [ ] Если лидеры слабые (рейтинг < 4.3, давно не обновляются) — идём дальше; иначе пересмотреть ниже в [[Анализ ниши и выбор]].
- [ ] Выбрать название и идентификатор пакета (`ru.<имя>.<приложение>`, менять после публикации нельзя).
- [ ] Решить вопрос с ИП (нужно для платёжек RuStore на этапе монетизации).

## Фаза 1. Каркас (2–3 дня)
- [x] Установить инструменты (см. [[Инструменты и скиллы]]).
- [x] `flutter create` в `app/` (org `ru.example` — **временный**, сменить до публикации), строгий линтер.
- [x] Структура feature-first: `lib/features/{expenses,subscriptions,budget,settings}` + `lib/core/{database,theme}`.
- [x] Riverpod 3 + Drift (таблицы категорий, расходов, подписок; схема v1 с миграциями), тема Material 3 светлая/тёмная.
- [x] `git init`, первый коммит. Удалённый репозиторий GitHub — ждёт уточнения.

## Фаза 2. MVP (2–3 недели)
- [ ] Добавление/редактирование трат (2 тапа), категории, суммы в рублях.
- [ ] Обзор месяца: итого, по категориям, диаграмма.
- [ ] Подписки: список, периодичность, дата следующего списания, локальное напоминание.
- [ ] Месячный бюджет и предупреждение о превышении.
- [ ] Экспорт CSV, резервная копия/восстановление из файла.
- [ ] Тесты на логику (бюджет, даты списания), виджет-тесты основных экранов.

## Фаза 3. Подготовка к публикации (3–5 дней)
- [ ] Иконка, скриншоты (5–8), краткое и полное описание с ключевыми словами.
- [ ] Политика конфиденциальности (страница в интернете; для приложения с рекламой обязательна).
- [ ] Release-подпись: создать keystore, хранить вне репозитория и **сделать резервную копию** (потеря ключа = невозможность обновлять).
- [ ] Сборка `flutter build apk --release` / `appbundle`, проверка на реальном устройстве.
- [ ] Регистрация в [RuStore Консоли](https://www.rustore.ru/developer) (VK ID/Госуслуги), загрузка, возрастной рейтинг, категория, отправка на модерацию.
- [ ] Прогнать скилл `mobile-release-check` (проверка debug-подписи, разрешений, ключей в коде).

## Фаза 4. Запуск и рост (месяц 1–2)
- [ ] Подключить Yandex Mobile Ads (регистрация в РСЯ, один нативный баннер).
- [ ] Подключить RuStore: обновления в приложении, push (по необходимости).
- [ ] Собирать отзывы, отвечать на каждый, править по ним.
- [ ] ASO-итерации: название/ключевые слова/скриншоты раз в 2 недели.
- [ ] Метрики: установки, удержание D1/D7, доход с рекламы (консоль RuStore + РСЯ).

## Фаза 5. Монетизация и развитие (месяц 2+)
- [ ] ИП, подключение монетизации в консоли, RuStore Pay SDK.
- [ ] Premium: без рекламы, виджеты, расширенная аналитика, бэкап-файл с шифрованием.
- [ ] Идеи роста: импорт из банковских выписок (CSV), семейный режим, цели накоплений.
- [ ] Рассмотреть iOS/другие магазины (Flutter позволяет), после стабильного дохода.

## Правила качества
- Каждая фича: модель → логика → тест → UI.
- Перед коммитом: `dart format`, `flutter analyze`, `flutter test` — должны быть зелёными.
- Зависимости добавлять только осознанно; версии проверять на pub.dev.
