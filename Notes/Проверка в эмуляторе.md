# Проверка приложения в Android-эмуляторе

Назад: [[Memory]] · [[Инструменты и скиллы]]

Эмулятор нужен, чтобы видеть приложение глазами: тесты Flutter не показывают реальный экран, уведомления и перезагрузку.

## Что установлено
- `C:\Android\Sdk\emulator` и образ `system-images;android-35;google_apis;x86_64` (скачано через `sdkmanager`, лицензии приняты пользователем 2026-10-14).
- AVD `ezh_pixel` (Pixel 6, экран 1080×2400). Ускорение: `emulator -accel-check` → WHPX usable.
- Образ без Play Store, поэтому доступен `adb root`.

## Запуск
```powershell
Start-Process "C:\Android\Sdk\emulator\emulator.exe" -ArgumentList '-avd ezh_pixel -memory 2048 -cores 4 -no-snapshot -no-audio -no-boot-anim -gpu auto'
```
Ждать `adb shell getprop sys.boot_completed` = `1` (холодный старт 1–2 минуты). Памяти ПК впритык (15,7 ГБ): с `-memory 3072` эмулятор тормозил и терял нажатия, с 2048 нормально. Остановить: `adb emu kill`.

## Установка и запуск приложения
```powershell
adb install -r "C:\Users\CENTICORE\Desktop\приложуха\app\build\app\outputs\flutter-apk\app-debug.apk"
adb shell am start -n app.ezhemesyachno/.MainActivity
```
APK собирать как обычно (в терминальной панели, см. `CLAUDE.md`). Первый запуск debug-сборки медленный (10–15 секунд).

## Управление и снимки экрана
- Снимок: `adb shell screencap -p /sdcard/s.png`, затем `adb pull` в scratchpad и `Read` по PNG. Снимок показывается уменьшенным в 1,2 раза: реальные координаты = отображаемые × 1,2.
- Нажатие: `adb shell input tap X Y`. Вкладки внизу (реальные координаты): «Ближайшие» 134,2232 · «Календарь» 404,2232 · «Платежи» 674,2232 · «Настройки» 944,2232.
- Ввод: `adb shell input text` умеет только латиницу и цифры. Между действиями делать паузы 2–4 с: эмулятор медленный.
- **Положение кнопок меняется, когда появляется клавиатура** (диалоги сдвигаются). Точные границы брать из дерева экрана: `adb shell uiautomator dump /sdcard/ui.xml`, затем `adb shell cat /sdcard/ui.xml` и искать `bounds` нужного текста.
- Кнопка «назад» (`input keyevent 4`) дважды подряд закрывает ещё и экран; скрывать клавиатуру одним нажатием и проверять снимком.
- Шторка уведомлений: `adb shell cmd statusbar expand-notifications` / `collapse`. Уведомления приложения: `adb shell dumpsys notification --noredact` (искать `pkg=app.ezhemesyachno`).
- Запланированные напоминания: `adb shell dumpsys alarm` (строки `Alarm{... app.ezhemesyachno}`, `origWhen` в миллисекундах Unix).

## Проверка по времени
1. `adb root`, затем `adb shell settings put global auto_time 0`.
2. Время менять **только** `adb shell cmd alarm set-time <миллисекунды Unix UTC>` (не `date`: AlarmManager не пересчитает будильники).
3. Приложение пересчитывает напоминания при запуске: сначала выставить время, потом `am force-stop` и `am start`, подождать пока будильники появятся в `dumpsys alarm`, и только потом ждать срабатывания. Запуск занимает ~13 секунд, на старте нельзя быть «внутри» минуты срабатывания.
4. В конце вернуть время: `cmd alarm set-time <сейчас>` и `settings put global auto_time 1`.

## Перезагрузка
`adb reboot`, дождаться загрузки, **не открывая приложение** подождать ~1–1,5 минуты: приёмник плагина запускает процесс и заново регистрирует будильники (проверять `dumpsys alarm`).
